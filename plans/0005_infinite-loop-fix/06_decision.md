## Accepted residual risks

Each of these is a known, deliberate gap. Ticking it means you accept it knowingly, not that you fixed it.

- [ ] **R3 / F9 — a session-cap pause resumes with only one session.** `pause()` marks the row `needs_operator`, `settleRow` puts it back to `pending` and sets `resumed_at`, so the next `drive` gives that row one session before pausing as a stall. A large but healthy milestone interrupted by the per-`drive` cap therefore pauses once per `drive` until it lands in a single session. Bounded, never a loop. Documented in `docs/how-it-works.md`; not changed because the pause *cause* is not machine-readable. The remedy is to split the milestone, not to re-`drive`. Reopen as "record the pause cause" if a real run hits the treadmill. *(Source: R3; `05_qa_plan.md` §3.7, decision 2)*

- [ ] **R5 — a milestone left `in_progress` at session end counts as a stall.** A session that runs out of context on a large milestone gets one retry, then pauses. Working as designed; changing it re-opens the bound this whole task exists to establish. Know it before writing five-file milestones. *(Source: R5; `05_qa_plan.md` §4)*

- [ ] **R6 — a legacy playbook pays `MAX_STALLED_SESSIONS` (2 paid sessions) on every `drive` at an undeclared human step** until someone adds an `Owner` column. This task's own playbook is one such file. The remedy is a one-line edit the operator makes once. *(Source: R6, D10; `05_qa_plan.md` §4)*

- [ ] **R7 — the no-push rule is prompt-only, and `radio` runs outside the guard.** `guard.ts` does not block `git push`, `gh pr create` or `gh pr merge`; only the execute prompt forbids them, and `radio` is unguarded at every stage including `need_operator`. Declared in `docs/security.md` and carved out as task #6. *(Source: R7; objective open question 6, ruled out of scope)*

- [ ] **R7b — QA's diff scope shrinks after a gate.** Work merged to `main` at an operator gate leaves `git diff main...HEAD`, so the QA lap can no longer see it; the QA prompt is told which gates the task paused at and opens with a diff-coverage statement, but the lost coverage is real. Carved out as task #7. *(Source: R7; M6)*
